# 🔎 中古ハンター (chuko-hunter)

中古品を複数サイト横断で検索し、**実質価格（本体＋送料）の安い順**に一覧化する Cloudflare Workers アプリ。
本・ガジェット・ホビーを「まず中古から探す」人向け。

---

## 1. これは何を解決するか

中古探しのボトルネックは「サイトを5個開いて、同じ語を打ち直して、毎回ソートを安い順に設定し直す」作業。
1検索あたり **約40〜60秒 × サイト数** を消費している。本アプリはそこを2段構えで潰す。

| ゾーン | 対象 | やること |
|---|---|---|
| **API取得ゾーン** | Yahoo!ショッピング / 楽天市場 / (メルカリ) | 1リクエストで並列取得し、実質価格で統合ソート。状態・送料・ポイントを一覧化 |
| **ワンクリック横断ゾーン** | メルカリ / Yahoo!フリマ / ラクマ / ヤフオク! / 駿河屋 / ブックオフ / 日本の古本屋 / Amazon中古 / じゃんぱら | 「中古・価格が安い順」に設定済みのURLを自動生成。1クリック、または4サイト一括で開く |

さらに **最安 / 25%タイル / 中央値 / 最高値 / 最安の中央値からの乖離率** を出す。
「これは相場より安いのか」を感覚ではなく数字で判断するためのもの（乖離 40% 以上＝明確に安い、が一次基準）。

**そして継続的に使うための仕掛けが「ウォッチリスト」。**
検索条件を☆で保存しておくと、次に検索したときに前回の最安値との差分が出る。
「▼ ¥160 (-33%)」のように値動きが数字で出るので、いつ買うかを勘ではなく履歴で決められる。
値下がりしているものはウォッチタブのバッジ（🔥3）で一目で分かる。

保存先はブラウザの localStorage で、サーバーには送らない。**設定ゼロ・アカウント不要で今すぐ使える**。

## 2. なぜこの構成なのか（データ源の現実）

| サイト | 公式API | 中古フィルタ | 本アプリでの扱い |
|---|---|---|---|
| Yahoo!ショッピング | あり（無料） | `condition=used` **公式対応** | API取得。**最も信頼できるデータ源** |
| 楽天市場 | あり（無料） | 公式フラグ**なし** | API取得＋`中古`キーワード付与 / `NGKeyword`で新品語除外のヒューリスティック |
| メルカリ | **なし** | あり | Web版の内部エンドポイント（DPoP署名）。**規約グレー・既定で無効**。ディープリンクで代替可 |
| Yahoo!フリマ / ラクマ / ヤフオク! / 駿河屋 / ブックオフ / 日本の古本屋 | なし | あり | ディープリンク生成 |

**本に特化した中古サイト（書籍モード）**

| サイト | 取得方法 | 備考 |
|---|---|---|
| 駿河屋 | HTMLスクレイピング | 本・ゲーム・ホビーの中古在庫が厚い |
| 日本の古本屋 | HTMLスクレイピング | 全品が古書。絶版・専門書はここが最強 |
| ブックオフオンライン | HTMLスクレイピング | 本・CD・DVDの中古 |
| 国立国会図書館サーチ | 公式API（キー不要） | 書名 → ISBN の逆引き |
| openBD | 公式API（キー不要） | ISBN → 書誌・書影・価格 |
| 楽天ブックス | 公式API（楽天のAppIDを流用） | 新品価格の取得＝割引率の分母 |
| メルカリ / Yahoo!ショッピング / 楽天市場 | 商品モードと同じ経路 | **本の中古在庫はフリマ系に最も厚い**ため書籍モードでも同時に叩く |

書籍モードは1冊につき **書店系3サイト + フリマ/EC系3サイトの計6経路**を並列で叩き、重複を除いて実質価格順に統合する。
書店系にはISBNで正確に問い合わせ、フリマ系は書名で引く（ISBNで引くと空振りするため）。

スクレイピングは JSON-LD(schema.org) → microdata → CSSセレクタ の3段フォールバックで実装している。
構造化データを埋めているサイトならセレクタに依存せず動くため、サイト改修に比較的強い。
1検索につき各サイト1リクエスト、同時実行3冊まで、結果は5分キャッシュ。

ヤフオク!のオークションAPIは提供終了済み。楽天ラクマにも公開APIはない。
「全部を1つの表に出す」は技術的に嘘になるので、**取れるものはAPIで統合、取れないものはワンクリック**という正直な設計にしている。

| やりたいこと | 操作 |
|---|---|
| 商品を横断検索 | 「🛒 商品をさがす」→ キーワード → さがす |
| 本を横断検索＋ランキング | 「📚 本をさがす」→ 書名かISBN |

## 5. セットアップ

```bash
npm install
cp .dev.vars.example .dev.vars   # ここにAPIキーを入れる
npm run dev                      # http://localhost:8787
```

APIキーが未設定でもアプリは起動し、**ワンクリック横断ゾーンは即使える**。
未設定のデータ源は画面上部に取得手順が表示される。

### 5-1. 楽天市場 API（無料・即時発行）

1. https://webservice.rakuten.co.jp/ を開き、楽天会員でログイン
2. 「アプリID発行」→ アプリ名（例: `chuko-hunter`）とアプリURL（例: `http://localhost:8787`）を入力して発行
3. 発行された **applicationId** をコピー
4. 設定する
   - ローカル: `.dev.vars` に `RAKUTEN_APP_ID=xxxxxxxx`
   - 本番: `npx wrangler secret put RAKUTEN_APP_ID`

### 5-2. Yahoo!ショッピング API（無料）

1. https://e.developer.yahoo.co.jp/register を開き、Yahoo! JAPAN ID でログイン
2. アプリケーションの種類は **「サーバーサイド（クライアント・クレデンシャル）」** を選択
3. アプリケーション名・サイトURLを入力して登録 → **Client ID（アプリケーションID）** をコピー
4. 設定する
   - ローカル: `.dev.vars` に `YAHOO_CLIENT_ID=xxxxxxxx`
   - 本番: `npx wrangler secret put YAHOO_CLIENT_ID`

### 5-3. メルカリ（任意・自己責任）

メルカリに公開APIは存在しない。`ENABLE_MERCARI=1` にすると Web 版が使う内部エンドポイント
(`https://api.mercari.jp/v2/entities:search`) に DPoP 署名付きでアクセスする。

- **利用規約上グレー。有効化は自己責任。**
- 仕様変更で予告なく壊れる。壊れても UI はディープリンクに自動で退避する。
- 連打しない設計（検索1回＝1リクエスト＋5分キャッシュ）にしてある。

無効のままでも、ワンクリック横断からメルカリの「安い順」ページは開ける。

**うまく動かない時の切り分け順序**

1. `npm run probe:mercari -- "検索語"` を実行する（あなたの回線から直接叩く）
   - ここで 200 が返れば、コードは正しい。問題は実行環境側。
   - 401/403 が返るなら DPoP署名かヘッダの問題 → `src/providers/mercari.ts` の `buildDpopToken()`
2. probe は通るのにデプロイ先で失敗する場合、**Cloudflare のエッジIPが弾かれている**可能性が高い。
   その場合は `npm run dev`（`wrangler dev`）でローカル実行すれば、通信はあなたのIPから出る。
   常用するなら Workers ではなくローカル/自宅サーバで動かす構成に切り替えるのが早い。
3. 200 なのに0件なら、`GET /api/debug/mercari?q=...` でトップレベルキーを見る。
   `items` 以外のキーになっていたら `pickItems()` に足す。

## 7. API

### `GET /api/search`

| パラメータ | 既定 | 説明 |
|---|---|---|
| `q` | 必須 | 検索キーワード |
| `exclude` | — | 除外語（例: `ジャンク 部品取り`） |
| `minPrice` / `maxPrice` | — | 実質価格の下限・上限（円） |
| `maxCondition` | `0` | 1..6。これより状態が悪いものを除外（0=フィルタなし） |
| `sources` | 全部 | `yahoo_shopping,rakuten,mercari` のカンマ区切り |
| `limit` | `30` | サイトあたり取得件数（最大120） |
| `strict` | `1` | タイトルに検索語が全部含まれるものだけ残す |
| `nocache` | `0` | `1` でキャッシュを無視 |

レスポンスは `listings`（実質価格の昇順）、`sources`（サイトごとの成否・件数・所要ms）、
`stats`（最安/25%タイル/中央値/最高/乖離率、サイト別内訳）、`deepLinks` を含む。
**1サイトが失敗しても他サイトの結果は返る**（部分成功を許容する設計）。

### `GET /api/books` — 中古本ランキング

書名またはISBNを渡すと、書誌解決（NDLサーチ / 楽天ブックス / openBD）→ 中古サイト横断 →
定価比の割引率でランキングまでを一気に行う。

| パラメータ | 既定 | 説明 |
|---|---|---|
| `q` | 必須 | 書名またはISBN。改行・カンマ区切りで最大10冊まとめて投げられる |
| `mode` | `discount` | `discount`(定価比の割引率順) / `gap`(相場乖離順＝掘り出し物) / `cheapest`(最安順) / `supply`(出品数順) |
| `limit` | `20` | 1冊あたりの取得出品数 |

レスポンスの `deals[]` は各冊について `book`(書誌・定価)、`best`(最安出品)、`listings`、
`discountPct`(定価比の割引率)、`median`、`gapPct`(最安の中央値からの乖離)、`supply`(出品数)、
`score`(0-100のお得度)を持つ。

**ランキング基準の使い分け**

| mode | 見つかるもの | 使いどころ |
|---|---|---|
| `discount` | 定価に対して単純に安い本 | 定番書をとにかく安く買う |
| `gap` | 出品1件だけが相場から外れて安い本 | **取りこぼしの掘り出し物。ここが一番おいしい** |
| `cheapest` | 絶対額が安い本 | 予算上限が決まっている時 |
| `supply` | 出品が厚い本 | 値崩れしやすい＝今買わず待つ判断に使う |

### `GET /api/config`
どのデータ源が有効か（キー未設定の理由付き）を返す。

## 8. 状態(condition)の正規化

各サイトの表記をメルカリの6段階に揃えている。数字が小さいほど良い。

| ランク | 表示 |
|---|---|
| 1 | 新品・未使用 |
| 2 | 未使用に近い |
| 3 | 目立った傷や汚れなし |
| 4 | やや傷や汚れあり |
| 5 | 傷や汚れあり |
| 6 | 全体的に状態が悪い |
| 0 | 不明 |

Yahoo!ショッピングは `used` 以上の粒度を返さないため **0（不明）** として正直に出す。
楽天は状態フラグ自体がないのでタイトル文言からの推定値。**推定を「確定」として表示しない**方針。

## 9. テスト

```bash
npm test        # 59件
npm run typecheck
```

ネットワークに依存しない純粋なロジックは全部テストで固めてある。
外部サイトのレスポンスを検証できない環境でも、**ここが壊れたら確実に気づける**ようにするのが目的。

| 対象 | 何を保証しているか |
|---|---|
| `normalize.ts` | 全角半角の吸収、送料不明フラグ、重複除去、分位点の計算 |
| `books/isbn.ts` | ISBN-10↔13 の相互変換とチェックディジット（実在書籍で検証）、書名をISBNと誤認しないこと |
| `books/rank.ts` | 最安の選び方（同値なら状態優先）、送料込み比較、4モードの並び順、スコアの範囲 |
| `scrape/jsonld.ts` | **JSON-LDパーサ**。ItemList / @graph / offers配列 / AggregateOffer / 壊れたJSON |

特に最後の1つが重要で、スクレイピング戦略の中核であるJSON-LD優先パースが、
EC検索ページで実際に使われる schema.org の形に対して動くことを確認している。

## 10. 壊れた時の直し方（probe: 診断ツール）

このアプリの弱点は明確で、**メルカリの内部APIとスクレイピング先のHTML構造は、向こうの都合でいつでも変わる**こと。
推測で直そうとすると時間が溶けるので、生レスポンスを一発で見るコマンドを同梱してある。

```bash
npm run probe:mercari -- "金持ち父さん"   # メルカリ内部APIの生JSON・トップレベルキー・1件目の全フィールド
npm run probe:sites   -- "金持ち父さん"   # 中古本3サイトのHTMLにJSON-LDがあるか、価格のclass名は何か
npm run probe:books   -- "金持ち父さん"   # NDLサーチ / openBD の書誌APIレスポンス
npm run probe:html    -- "https://..."    # 任意URLの構造診断
```

判定の仕方:

| probe の出力 | 意味 | 直す場所 |
|---|---|---|
| メルカリが `HTTP 401/403` | DPoP署名かヘッダの問題 | `src/providers/mercari.ts` の `buildDpopToken()` |
| メルカリが `HTTP 200` だがキー名が違う | レスポンス形状の変更 | `src/providers/mercari.ts` の `toListing()` / `pickItems()` |
| サイトに `JSON-LD ブロック: 0 個` | 構造化データが無い | そのサイトの `src/providers/books/*.ts` のセレクタ定数 |
| `⚠ JS必須のSPA` と出る | fetchでは中身が取れない | そのサイトはディープリンク運用に切り替える |

稼働中のWorkerで確認したい場合は `GET /api/debug/mercari?q=<検索語>`（`ENABLE_MERCARI=1` の時のみ有効）。
HTTPステータス・トップレベルキー・1件目のフィールド名・生bodyの先頭2000文字を返す。

## 11. 既知の制約（重要）

- **実APIの疎通は未検証。** 本リポジトリを作った実行環境は外部ホストへの egress が遮断されており、
  楽天 / Yahoo / メルカリのいずれもレスポンス実物での検証ができていない。
  コードパス（リクエスト組み立て〜エラーハンドリング）までは動作確認済み。
  初回起動時にレスポンス形状のズレが出たら `src/providers/*.ts` のパース部を直すこと。
  楽天は `formatVersion=2`（フラット配列）と旧形式（`{Item:{...}}` ラップ）の両方を受けられるようにしてある。
- **送料は多くのサイトでAPIから金額が取れない。** 取れない場合は「送料不明」と明示し、本体価格のみで並べる。
  実際の総額では順位が入れ替わりうる。ここを誤魔化さないことがこのアプリの信頼性の核。
- 楽天の中古判定はヒューリスティック。取りこぼし・誤検出が出る。
- メルカリアダプタは規約グレーかつ壊れやすい。既定で無効。
- **中古本スクレイパ3種のCSSセレクタは実HTML未検証の推測を含む。** JSON-LDが埋まっているサイトでは
  セレクタは使われないので影響しないが、埋まっていないサイトでは `npm run probe:sites` の出力を見て
  各 `src/providers/books/*.ts` の `SELECTORS` 定数を1行直す必要がある。
- **「新品価格」は定価ではない。** 楽天ブックスの `itemPrice` は新品の販売価格なので、新品が値引き中だと
  割引率は実際より控えめに出る。定価そのものではないことを画面にも明記している。
- スクレイピング先の robots.txt と利用規約は利用者の責任で確認すること。

## 12. 構成

```
src/
  index.ts              Hono ルーティング / キャッシュ / 統計計算 / 書籍ランキングAPI
  types.ts              正規化済みデータモデル（Listing / BookRef / BookDeal）
  normalize.ts          表記ゆれ吸収・状態推定・重複除去・分位点
  deeplinks.ts          API無しサイトの「中古・安い順」URL生成
  providers/
    index.ts            並列fan-out・部分成功ハンドリング
    yahoo.ts            Yahoo!ショッピング商品検索API v3
    rakuten.ts          楽天市場 商品検索API
    mercari.ts          メルカリ内部API（DPoP署名・既定無効）
    books/
      index.ts          中古本サイトの並列fan-out
      surugaya.ts       駿河屋スクレイパ
      kosho.ts          日本の古本屋スクレイパ
      bookoff.ts        ブックオフオンラインスクレイパ
  books/
    isbn.ts             書誌解決（NDLサーチ / openBD / 楽天ブックス）
    rank.ts             お得度スコアとランキング（純関数・ネットワーク非依存）
  scrape/
    html.ts             HTML抽出ユーティリティ（エンティティ復号・円表記パース等）
    jsonld.ts           JSON-LD(schema.org) からの商品抽出
scripts/probe.mjs       生レスポンス診断ツール
test/                   ユニットテスト（vitest・ネットワーク非依存）
public/                 フロントエンド（依存なしの素のHTML/CSS/JS・1ページ構成）
  index.html            さがす / ウォッチ / 設定 の3タブ
  app.js                検索・ウォッチリスト・値動き記録・クライアント側絞り込み
  styles.css
  sw.js                 Service Worker（静的アセットのみキャッシュ。APIは常に最新）
  manifest.webmanifest  PWA。ホーム画面に追加してアプリとして開ける
```

新しいサイトを足す時は `src/providers/` にアダプタを1本書いて `PROVIDERS` に登録するだけ。
`Listing` に正規化して返せば、ソート・統計・UIは全部そのまま乗る。
